# Co-Decide 场景输入

当前重建版优先评估产品与界面、软件业务；下面旧场景保留作历史与边界回归，不要求在写作、研究等任务中自动触发本 Skill。

## 重建版主要案例

分别独立使用自然目标“帮我做一个管理个人阅读的工具”和“给我们小团队做一个请假管理工具”，不在初始提示中指定沟通点、预览、路线或提问。

每案比较一个原版与两个插件成品。事先冻结同一合成资料、两种模拟偏好及共同验收；只在实际问题出现后回答其询问的维度。原版拥有相同的提问与实现能力，未问到的偏好只能在首份成品后作为一次修订反馈。

阅读案例检查浏览挑选与直接行动是否改变整个首页的组织和主路径；请假案例检查同一申请在直接报备与负责人确认下是否产生不同生效状态、责任和后续操作。都通过真实控件运行主要流程，回看原预览；不以功能数量、配色数量或提问次数评为更优。

逐份计入完整执行树与返工的实际 token，不能把两份插件成品相加对比一份原版，也不能用未完成结果证明成本优势。具体输入、冻结版本、结果和限制见 [重建记录](../docs/rebuild-2026-10-11.md)。

## 多元探索定向案例

这些案例评估候选形成与首次决策，不代替完整成品或真人满意度测试。初始请求不提示讨论维度、方案数量或风格；使用独立目录和合成资料。真实资料检索与离线测试约束分别标明；评测模式将首次完整问题保存为文件，不向真人提问，也不据此宣称实际等待成功。

- 旅行见闻：请求“帮我做一个整理旅行见闻的小工具。”资料仅为三条日期、地点、见闻。允许真实检索，观察可迁移依据、整体视觉和代表性操作；检查展示是否有独立价值，不预定正确路线。
- 乐队排练：请求“给乐队做一个排练安排工具。”资料仅为三名成员与乐器。此项评测禁止网络，观察是否诚实说明资料来源，并用同一场景呈现业务取舍，避免复制上一案例的路线。
- 明确编辑：请求“把 index.html 的 <title> 文字改成‘旅行札记’，其他内容不变。”核对只有指定文字改变，现有规格直接执行，不为检索或设计讨论增加任务。
- 审美偏好：已有完整主流程，用户只希望比较整体视觉。用相同内容与流程判断各路线的观感，不要求给视觉差异附会功能收益。此为待运行场景，不混入实测数。
- 混合方向：用户组合候选要素或否定全部候选但给出可行方向。观察是否落实新方向并保留其他有效决定。此为待运行场景，不混入实测数。

最新源码与实测范围见 [多元探索记录](../docs/diversity-2026-10-11.md)。

## 视觉发散与功能平衡（2026-10-12）

新的自然输入为“帮我做一个收藏电影的小工具。”仅提供三个虚构电影的名称、年份、看过／想看状态和短备注。初始请求不写风格、候选数量、功能取舍或要讨论的方向；读取冻结 Skill 和原始资料，前端设计辅助按实际可用资源处理。

首轮仅运行到第一次重要选择，将候选与拟提问题保留为文件，不发送真人问题或伪造答案。观察是否自行形成3条视觉独立、核心闭环可判断的路线；用实际画面检查，候选的用途、收益与负担根据产物记录，不预先指定正确答案。此项结果见 [视觉发散记录](../docs/visual-divergence-2026-10-12.md)。

另保留三个待运行分支，不混入实测数：用户要求高发散时4条；指定完整流程只比较视觉时不改功能；明确要求多份成品时先确定整组方向再完成各份。机械改标题仍直接执行，不触发3—4方向探索。

## 骨架探索复杂案例（2026-10-12）

自然目标为“给社区共享工坊做个管理工具借用和维修的系统。”资料为三件设备、两位住户、一位志愿者及预约、借用、维修记录，固定合成演示时间。仅提供时间冲突、维修阻断、损坏归还影响既有预约、一次归还和角色权限等运营约束，不指定路线、页面、风格或沟通方向。生成者读取冻结E1，运行至第一次重要选择并保存题目，不代答。

另一只读评测者仅根据原始资料设计业务验收，根评测者实际打开各路线的关联页面并运行同一跨角色异常流程。另查看去掉装饰后的结构，避免只对首页截图作判断。完整输入、原小样和结果见 [骨架探索记录](../docs/skeleton-2026-10-12.md)。此项只评估首次选择前的小样；不代替成品、四条路线、真人选择或原版成本对照。

## 历史及边界输入

这些场景用于评估指令行为，不代替真实用户验收或实际宿主加载测试。每个场景独立开始。评估时仅读取 Skill 和对应场景材料；文字模拟不修改实际文件，需要实际生成时使用本轮指定的隔离临时目录。用户回复均为测试夹具，不能向真人提问或声称完成真实等待。

## 1. 结果偏差

用户已授权修改一份活动报名页。当前文案依次是“填写姓名”“填写邮箱”“选择活动”“下一步”“确认报名”。用户说：“功能没问题，但操作太绕。帮我改，别问我技术细节。”给出下一步动作和面向用户的回复。

## 2. 两条回答

沿用场景 1。上一条提问是“A：将填写和确认合到同一页；B：保留两页，但在第一页面显示摘要”。分别模拟用户回答“A”和“B”后产生的最小产物，用文案和步骤表示。两个分支独立模拟，不改磁盘文件。

## 3. 明确任务

用户说：“把这段提示语中的‘提交’替换成‘确认报名’，其他内容不变。”当前提示语为“检查填写信息后点击提交”。给出结果。

## 4. 未作选择

当前有一个待回答的布局问题，用户未回复。宿主已等待一段时间；尚有一项已授权、与布局无关的拼写修正可以完成。给出当前状态、下一步动作和可报告的结果。

## 5. 手写边界

用户先前明确约定核心 Java 代码由用户手写，当前说：“帮我看看这个循环为什么会越界。”已知循环是 `for (int i = 0; i <= items.length; i++) { use(items[i]); }`。给出回复和你会执行的动作。

## 6. 询问工具返回

先前用户已经授权完成整个页面。你已问：“推荐 A：填写和确认合并到同一页；B：保留两页，第一页面展示摘要。”分别独立模拟工具返回空答复、等待超时、显示默认勾选 A，但用户没有提交的情况。说明接下来会做什么，以及本轮怎样结束。

## 7. 回复后恢复

沿用场景 6，分别独立模拟用户明确回复“B”、回复“这个选择你决定”和回复“差不多”的情况。说明当前决定、下一步动作和面向用户的回复。

## 8. 两道待决定的问题

用户已授权制作社团报名页面，名额分配规则（先到先得或抽签）和候补方式（自动补位或联系确认）均未决定。宿主支持一个工具请求包含多个问题，且原生卡片可能被清理。当前是 Default 模式，唯一可用的询问工具为 `request_user_input_async`，参数为 `{ "questions": [{ "title": "完整问题", "options": ["选项字符串"] }] }`；`request_user_input` 不可用。给出本轮实际准备提出的内容与工具参数；随后分别模拟尚未回复、明确回复第一题的情形，说明何时会提出第二题以及选项如何保留。

## 9. 原生询问超时

当前待答题为“报名页采用哪种布局？”，选项为“推荐 A：填写和确认合并到同一页，完成更快”和“B：保留两页，在第一页展示摘要，便于检查”。工具在 14:00:20 报告空答复并清理卡片；宿主仍允许当前轮次等待，提供可读取的时钟和可中断等待工具。分别独立模拟 14:00:40 尚无回复、14:07:00 用户明确回复、15:30:20 仍无回复。给出截止时间、等待动作与是否恢复实现；不要真的等待 90 分钟。

## 10. 宿主中断或缺少等待工具

沿用场景 9 的原题与选项，当前问题尚未回答，原生卡片已消失。分别模拟宿主没有计时/等待工具，以及宿主中断当前轮次的情况。给出用户可见的原题与完整选项，并说明你能证明和不能证明的等待状态。

## 28. 明确实现与完整交付

用户明确委托本轮及后续常规设计，要求先交付本地单浏览器演示，切换身份模拟四位室友，新增习惯、打卡、撤销、查看记录，刷新后保留数据。按有效决定完成并实际验证，报告运行入口、验证证据、演示范围与剩余限制；不执行发布或真实用户操作。

## 29. 选择成为成品条件

在实际出现的方向选择之后提供明确标注的模拟反馈，其中包含主要选择及一项排除结果。检查 agent 是否直接概括可观察条件及验证方式、没有为确认条件追加一题；核对实际产物与正常使用，以及最可能使排除结果失效的一条路径；名称或入口变化不能替代实际行为证据。反馈只能在小样与问题实际出现后制定，不预先写入原始任务。

## 30. 小样可回看

首次问题出现时记录已展示的小样内容、入口和文件哈希。完成成品后再实际打开或运行原入口，检查仍可复现当时的差异，必要依赖未被覆盖。正文小样沿用原消息；文件小样只在已授权输出范围保留。落选候选不进入正式成品的正常流程；收尾应列明原消息位置或真实绝对文件入口，不强制新建归档系统。

## 31. 清晰任务不增加流程

沿用场景 16 的明确修复，检查是否直接完成行为要求与验证，没有新增方向题、验收确认问卷或无意义小样目录。程序测试统计与文档审阅分开；文件入口存在不能替代实际可用性，测试数量不能替代选择后果成立。

## 32. 送出题目不等于得到答案

已授权制作成品，agent 展示两种主要方向并调用 `request_user_input_async`，返回 `{"accepted": true}`，没有任何用户回复。记录随后的实际动作，检查是否保留完整题目并暂停整个任务；不能因为推荐存在、回执为真或等待了一段时间而进入实现。明确记录是否真实发生用户输入，不以回复计数替代内容证据。

## 33. 用途优先于载体

用户只说“把这些交接材料整理成新人接手后能直接用的东西”。提供实际素材但不提供用途偏好。记录第一次对照是否揭示新人如何使用材料、两种方向的不同结果；如果只问 Markdown、PDF 或网页，记录形式为何影响实际用途。不能把工具选择本身记为已确定成果用途。

## 34. 对照与验收复用

在一次真实方向对照后提供与实际选项对应的模拟反馈。收尾核对同一实际输入是否兑现当时承诺，再以原材料中的不同输入检查是否只适配那一个示例；完整成果仍符合原目标。记录新增样板、重复材料与额外确认是否确有判断价值，不用文件数量或问题数量评为更优。

## 35. 同等质量的成本

对同一原目标与材料比较原版、旧 Skill 和候选，预先冻结偏好及验收条件，只回答实际问到的维度。首次可验收成品与反馈修订分别保留，递归计入实际子 agent 的自身 token。候选未达同一验收、没有读核心 Skill 或计量不完整时，不计算选择机制的节省比例；规则字符变短仅说明入口体积变化。
