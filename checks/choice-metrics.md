# 选择效果评测协议

Co-Decide 的评价单位是用户选择改变的成品行为，不是问题数、小样数或用户回合数。本协议是开发评测材料，不加入运行 Skill 的上下文或安装配置。

## 四项主指标

1. **定型前识别**：影响主体的未定偏好，是否在相关流程或正文成形前由用户明确确定。既有材料中的事实、安全规则和正确技术做法不算新增共同决策。
2. **选择兑现**：最终通过的已明确选择条件 / 已明确选择条件。条件须来自用户反馈、候选承诺或原目标；记录每一条的具体内容、实际结果和验证。未披露偏好不能记为模型忽视了反馈，但仍可纳入最终适配程度。
3. **选择敏感性**：同一原目标与材料，换一个主要答案后，核心状态、内容组织或使用流程是否真的改变。只换名称、文案或颜色不足以证明机制变化；本来只涉及审美的选择以实际可见差异验收。
4. **同等验收成本**：达到同一全部硬条件所需的完整 token。首次成品与修订后成品分开报告；一方不达线、计量不完整或额外预算时，不计算精确节省比例。有明确计量下界时仅单列可证明的保守界限，不估算缺失费用。

同时记录首次成品的偏好满足率、交付后方向改动、技术性恢复、小样回看入口。用户参与是明确决定的影响，不以“让用户多说几次”代替价值。

探索质量另行观察：外部范例如何改变候选假设；各路线在视觉、组织、交互或业务结果上的独立价值；推荐之外的路线是否同样认真、可行。纯审美选择用真实内容和整体视觉检验，不强求功能分叉。参考数量、选项数量和浏览次数不当作质量分数；小样阶段的成功不等同最终选择兑现或成品成本优势。

## 公平基线

原版保留正常提问、候选、研究、小样和改稿能力；实际提前问到关键问题就照答。不得提示它先做错、禁止提问或固定多轮返工。两组使用相同模型档位、原始材料、反馈机会与验收规则。模拟用户偏好先冻结，问题实际问到哪一项才披露哪一项；没问时只在可验收成品出现后反馈未满足项，允许混合或否定候选。

加入明确、无需偏好讨论的任务作为负对照。没有调用核心 Skill 的运行，其 token 差异不可归功于选择机制。

## 计量与判定

计量包含小样、询问、读取、实现、失败、恢复及修订；有子 agent 时计入递归会话树，每个自身线程及 response_id 去重，剔除复制的父历史，不重复相加累计值。输入已含缓存输入，输出已含推理输出。报告输入、缓存、非缓存输入及输出，原始总量为 input+output；不将 token 直接等同人民币或订阅额度。

先核验实际 Skill catalog 和读取来源；参数声明不代替生效证明。缺账或未完成生成标不可比较，不当零。模拟用户和独立评审费用单列。阶段超时单独报告，不从一次技术事故推导选择机制的因果优势。

成品的硬条件优先于审美总分；真实浏览器行为、打印页数或独立函数调用优先于源码检查和作者自述。独立模型匿名审查不能称为真人满意度测评。少量单次生成只支持这些样本中的差值，不支持普遍胜出或固定节省百分比。

方法参考：[OpenAI 的 Skill 评测实践](https://developers.openai.com/blog/eval-skills)，使用执行轨迹和运行时证据，而不只匹配文字。
