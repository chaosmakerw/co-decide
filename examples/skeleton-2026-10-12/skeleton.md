# 工坊三路线方向小样

入口：index.html。一个文件包含本地 CSS、SVG 和 JavaScript，可直接双击，无框架、服务、安装和联网依赖。原始 records.json 与 operations.md 保留不动，页面内嵌与其相同的基线资料。角色切换只是本机演示，不代表身份认证。

## 先探索，再收敛

冻结版 Co-Decide 默认中档、目标三条整体路线。探索时曾考虑设备目录、按天时间表、志愿者队列、场地区域地图。场地地图缺少区域位置与实际空间关系，不适合用虚构空间作判断依据，因而舍弃。按天路线继续聚焦“人的一程”而不是全设备时段矩阵，避免与设备目录只是换表格。保留三条，差异涉及进入者、信息主体、导航、页面关系和操作顺序。

资料已经决定了住户管理自己预约、志愿者办理实际借出/归还/维修，以及损坏对已有预约的处理。候选没有让用户选择这些正确性要求。未决定的是系统围绕“设备”“人的使用过程”还是“需要处理的事项”组织日常入口。这一选择会贯穿关联页面，因此在正式完善前比较。

## A · 器物目录

信息主体：设备。暖纸色、工具图形、档案式栏目。

住户：全部设备 → 设备档案/时段 → 预约弹窗 → 我的预约 → 设备状态/交接记录。
志愿者：全部设备 → 设备档案 → 接收归还 → 同设备维修 → 原预约交接。
关联导航：全部设备、我的预约（住户）、维修履历（志愿者）。维修履历再回设备档案。

A 的业务闭环在同一件器物档案内连续完成。借还和维修不另建独立后台；设备页同时呈现已有预约与当前借用。代价是志愿者需从器物找到动作，多设备待办不集中。

## B · 我的工坊日

信息主体：人的当天使用/交接。暖橙纸张、墨黑票框、针脚分隔与连续时间线。

住户：我的今天 → 一条自己的预约/借用 → 当前步骤与下一步 → 找工具 → 工具详情/预约 → 回到当天安排。
志愿者：交接簿 → 小禾的这次交接 → 接收归还 → 同设备检修的一程 → 阿澄下一程 → 实际借出/归还。
关联导航：我的今天、找工具；志愿者为交接簿、检修进度、工具。

每个案页把本次使用的人、时段与下一位的预约连接起来。检修不只显示设备“坏了”，还解释后面那个人为什么要等待。代价是纯粹浏览设备需要切到找工具，维修在按人按时间的组织里更分散。

## C · 值班台

信息主体：待办理事项。深色维修设备面板、荧黄动作、固定侧栏、分列队列与方形案卷。

志愿者：今天的交接 → 待归还 L01 案卷 → 接收 → 待维修 M02 案卷 → 完成 → 待借出 B02 案卷 → 实际借用 L02 → 归还。
住户：我的事项 → 自己的预约/借用案卷 → 状态与取消预约；设备台账 → 设备详情 → 预约。
关联导航：今天的交接/我的事项、维修队列（志愿者）、设备台账。

队列组织入口，案卷提供完整关联事实，动作区处理当前事项。已归还借用不会继续停在待归还列，维修完成留档。代价是住户找工具多一个台账入口，界面更像现场工作台。

## 共用输入与状态约束

演示日固定 2026-10-13 10:00，全部事件记录按这个固定演示时刻标记，不代表现实发生时间。原始业务未指定不得提前交接，因此小样没有添加“必须到 11 点才可借出”的新规则；预约时段与现场确认时刻分别记录。

1. T02 当前借用 L01：小禾 09:00–11:00；下一条 B02：阿澄 11:00–12:00。
2. 志愿者接收 L01，选择损坏并填写问题：L01 returned；T02 maintenance；新增 M02 open，关联 loan_id=L01。
3. B02 保持 confirmed，受影响状态由设备 maintenance 派生。住户看到“原预约保留”，志愿者尝试借出被拦截，不产生新借用。
4. 志愿者完成 M02：M02 done，保留问题与完成时刻；T02 available；B02 仍 confirmed，可继续办理。
5. 实际借出 B02：新增 L02 active，关联 reservation_id=B02；B02 fulfilled；T02 borrowed。正常接收 L02：L02 returned，T02 available。重复归还入口移走/禁用，状态操作也拒绝重复接收。

预约用半开区间相交判定 start < other.end && end > other.start。T01 已有 10:00–12:00，预约 11:00–12:00 会被拦截，12:00–13:00 可以。取消预约保留记录，只允许住户取消自己的 confirmed 预约。维修设备不开放新增预约且拦截实际借出。

状态仅在内存。刷新复原，点击重置复原；三路线切换保留相同状态用于比较。小样没有押金、付款、短信、真实登录、数据库、真实权限校验和场地接入。

## 检查入口与控件

参数：route=assets|journey|desk，persona=R01|R02|V01。默认 A/R01，直接进入 C 时默认为 V01。可追加 view=detail&asset=T02 直达设备页。日常换页用导航，不需要参数。底部路线切换 [data-route="assets"]、[data-route="journey"]、[data-route="desk"]。重置 #reset。演示身份 #persona。

只读观察：window.workshopDemo.snapshot() 返回全部内存状态副本；window.workshopDemo.fixtures() 返回基线副本；window.workshopDemo.ui() 返回当前路线、角色、页面与案卷副本。没有给观察入口提供写入/操作方法。

连续损坏场景：
- A：切 V01，点 [data-open-asset="T02"]，点 [data-return="L01"]。
- B：切 V01，点 [data-open-case="loan:L01"]，点 [data-return="L01"]。
- C：初始 V01，点 [data-open-case="loan:L01"]，点 [data-return="L01"]。
- 共用表单：勾 #return-damaged，填写 #return-issue，点 #confirm-return。可见维修提示 [data-impact="T02"]，B02 保留，历史增加归还/维修关联。
- 查看住户结果：#persona 选 R01。A 再点 [data-nav="mine"]；B/C 首页直接显示自己的 B02 与受影响提示。
- 再切 V01：A 进入 T02 设备页；B/C 点 [data-open-case="reservation:B02"]。点 [data-checkout="B02"] 可见 #toast “借出已停止”，状态不变。
- 完成维修：A 点 [data-repair="M02"]；B/C 可点 [data-open-case="repair:M02"] 后 [data-repair="M02"]。弹窗点 #confirm-repair。
- 借出 B02：A 设备页点 [data-checkout="B02"]；B/C 完成后的维修案卷点 [data-open-case="reservation:B02"]，再 [data-checkout="B02"]。生成 L02，B02 fulfilled。
- 正常归还 L02：A 设备页点 [data-return="L02"]；B/C 点 [data-open-case="loan:L02"] 再 [data-return="L02"]。默认正常，点 #confirm-return。记录保留，设备恢复可使用。

预约边界：重置；R01；设备 T01（A 首页、B 找工具、C 设备台账）；[data-book="T01"]；#book-start/#book-end 填时段；#confirm-book。非法结束不晚于开始、重叠时段显示 #form-error，不新增记录；12:00–13:00 新增 B03。取消按钮 [data-cancel="B03"]，原记录保留。
