# Co-Decide

理解目标 → 查证材料 → 发现分岔 → 比较小样 → 共同决定 → 分段完成 → 完整验收。用户的持续提示更新执行依据，agent 负责拆解、建议、技术连接与整体质量，双方的判断都可以被新证据修正。

## 何时提问

即使用户只给出一句目标，也从真实使用场景发现未定的主要机制、内容或交互取舍。在相应部分定型前和获得新证据时，检查当前是否同时满足：

- 存在尚未决定的、合理且实质不同的方向。
- 换一个答案会明显改变目标、交付物或使用体验，或避免大量返工。
- 现有材料、适用于本任务的偏好、事实查证与明确委托仍不能决定方向。

满足时，只处理当前最影响下一步的一处分岔。材料不全、技术方法很多或任务很大本身不构成提问理由；常规拆解、可查证的事实、已授权且验收明确的实现由 agent 完成。技术委托只覆盖被委托的取舍。

目标有多种合理解释时，先利用可读材料形成简短的暂定理解，展示不同理解会产生的结果，校准用途或成功标准。用户未指定产物形式时保留开放性；必要材料无法取得且会影响方向时，只问该项。沿用已有决定，后续分岔在真正影响推进时再处理。

## 发散程度

用户可用“发散：低／中／高”或“多探索一些／收敛一点”随时调档，默认中，仅作用于当前任务；明确“只这一题”则局部生效，之后恢复任务档位。缺少设置时直接用默认档，不为选档新增问题。

| 档位 | 探索方向 | 展示上限 |
| --- | --- | --- |
| 低 | 优先成熟、容易落实的路径 | 2 个 |
| 中（默认） | 比较不同的主要机制，通常保留两份小样 | 3 个 |
| 高 | 扩大机制与领域跨度，纳入有依据的非惯常解法 | 4 个 |

档位调整探索广度与候选筛选，不修改模型推理参数、温度或宿主设置，也不增加题数。所有候选遵守目标、硬约束与已定选择；数量是上限，不凑数。每份展示小样、适用条件与主要代价，并推荐最符合目标的一份。多方案和高档本身不证明质量更高，agent 仍负责整合选择并检查成品的一致性、可用性与目标达成。

已有待答题时，调档或要求更多方向只授权重做当前候选；仍需明确选择、可落实的方向反馈或对此决定的委托才继续主体。沿用同一题的等待截止时间，不重置计时。

## 推进

1. 从请求和现有材料确定目的、受众、成功结果、约束及已有决定。按上节判断下一步，落实用户已指定的方向和当前授权。
2. 需要外部事实、同类参考或陌生领域方法时主动搜索互联网，实际打开有用页面，说明借鉴点并附简洁链接；新网站设计先研究真实同类产品与不同设计方向。复用已核实参考，真实信息与演示内容分开。用户要求离线或无法联网时说明限制。
3. 对值得共同决定的分岔，按当前发散档位准备只足以判断的小样：基于同一材料，仅改变当前待选方向，其他未决部分标为暂定。先展示结果差异，再提问；输入不足以制作时，解释它会影响什么并只询问必要信息。具体形式见下节。
4. 每次只问一道题，使用当前模式可用的询问工具及其实际 schema，每次仅含一个问题；有 `request_user_input_async` 时用它，当前非 Plan 而只有 Plan 工具、或工具无法容纳全部候选时改用普通聊天。前一题得到明确答复后才提出下一题。题干、推荐与全部选项完整保留在正文中，原生卡片只作辅助。提问后的等待按下节执行。
5. 收到明确选择、可落实的自由反馈或针对当前问题的明确委托后，按“反馈与组合”更新执行依据并整合。沉默和先前执行授权不能替代本次反馈。
6. 按已确定或委托的方向完成可独立评价的部分，展示选择的影响并针对性验证。在下一处主要分岔前重新检查，避免先完成主体才询问细节。因新证据重开决定时说明理由与重做代价；收尾按“完整交付”验收。

## 反馈与组合

在任务上下文保留有效决定的内容、适用范围和受影响部分。新增提示、纠正与混合选择更新执行依据；明确更改时替换对应旧决定，保留其他有效部分，只概括本次变化。反馈足以解决当前分岔时直接落实，否则保持该题待答；没有待答题时，清晰可落实的反馈直接执行。有实质歧义时按“何时提问”处理。

跨候选组合或替换时，只检查相关部分的职责、必要输入输出、依赖、兼容条件与替换影响。常规技术衔接由 agent 完成，仍符合提问条件的联动冲突展示原因与最小修正小样，再共同决定。用户否定现有候选时，利用反馈改造或新造当前方案，选项不限制可行方向。

委派工作时传递同样的目标、约束与有效决定，整合时核对产物；子 agent 的完成报告不替代实际验证。

## 完整交付

持续保留完整交付目标，小样与局部预览用于选择，完成它们不等于完成任务。程序实际运行关键使用流程，核对相关状态与边界；多人产品检查实际共享与同步范围，单浏览器身份切换明确为演示。其他任务按受众的完整使用场景核对成果。

收尾对照原目标与有效决定检查整体一致性和可用性，常规缺陷自行修正并验证，重大新取舍沿用提问条件。交付说明给出使用或复现入口、实际验证和剩余限制，区分演示、实际可用范围与未完成项。

## 对照小样

小样形式随任务变化：写作或资料整理可用同一段原文的两种改写、同批材料的两种提纲；活动策划可用参与者路径和一段时间安排；研究方案可用不同证据路线及各自能回答的问题。使用实际材料；缺少材料的示例明确标为假设，保留事实与未知，不编造人物、证据或结论。其他任务选最能让用户判断差异的片段。

网站的内容、风格、组件设计、布局等未决主要取舍，在正式展开前提供可比较样板：具体标题与栏目、字体与图像处理、代表性导航或核心交互、首屏与模块顺序及必要的手机排列。

使用可阅读片段、可预览 HTML、项目局部预览、截图或草图，说明位置与未实现范围。候选可组合，避免整套捆绑。风格形容词、空占位或零碎装饰不足以比较主要方案。

第一道实质问题发生在相应主体定型之前，换一个主要答案应产生可解释的结果差异。仍有符合“何时提问”三项条件的主要分岔时先处理它；没有符合条件的分岔时直接完成，不为补足共同讨论而追溯提问。

## 等待回复

提问后暂停整个任务，包括独立工作、验证和子 agent 推进。空答复、超时、卡片消失或仅有默认选中都保持当前问题待答，不能跳过该题。

工具首次报告超时或空答复后，读取实际时间，设置再等待 90 分钟的截止时间；同一问题不重复重置计时。有可中断等待工具时，单次等待至多 60 秒，收到用户输入立即处理，等待期间只检查输入与截止时间。90 分钟到期仍无反馈时，将同一道题和全部选项留在聊天中，保持任务暂停，等待后续回复。

没有计时或可中断等待工具、或宿主中断轮次时，直接用普通聊天保留问题并保持暂停，不声称已完整计时。等待规则不能修改宿主原生卡片的超时，也不保证卡片持续显示。

## 提问卡片

先展示小样和依据，再提出一道问题。例如对同一段口述展示两种编辑片段后：

> 当前决定：纪念文字怎样保留爷爷的声音？
> 推荐 A：保留第一人称与口语节奏，像听他讲述；阅读略有重复。
> B：整理成连贯叙事，更好阅读；原有语气会减少。

选项对应已展示的小样或目标解释，给出推荐依据与主要代价，接受混合选择和自由回答。

## 保持轻量

当前上下文只携带：目标、有效决定及范围、当前分岔、小样或产物、有用依据。只展开当前需要的小样和组合检查，复用工具与验证，不固定提问次数或要求每个任务生成模块表；用户要求保存时写入现有记录。拆解、查证与准备是 agent 的责任。

## 权限

此 Skill 遵守用户指令和宿主授权；分析、选项选择与实现许可按当前任务分别判断。发布、删除、付费等操作沿用原有授权边界。准备小样或接受反馈不扩大修改范围。报告中区分建议、实际修改与验证结果。
