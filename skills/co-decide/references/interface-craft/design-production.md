# 构思与制作

用于新产品、多路线探索或整体重设计。目标是让重要选择在成品之前可见，把预算用于画面和操作；已有明确设计时直接沿用。

## 先确定做什么、怎样做

在写完整产品前，为每条路线留下几行制作说明；已有材料能够回答的直接填好：

- **体验与内容**：谁在什么情境下使用，最想完成什么；首屏先看什么、先做什么，其余内容放哪里。
- **骨架与结果**：入口、主体信息、主操作到结果的路径。功能取舍说明得到什么、付出什么。
- **画面与素材**：用一句具体构图描述画面重心、字形和尺度、空间关系、色彩角色，以及素材或原创图形怎样参与；说明关键页面怎样延续这一语言。
- **制作与动作**：用什么可获得的资源、代码与组件实现；窄屏如何重排；关键动作怎样让状态变化可见并可恢复。

这是可以核对的制作方案，不是长篇设计论证；相同事实只记一次。纯排版也要有构图和字级，具象素材要有角色、焦点和裁切，原创图形要服务内容。选择适合目标的媒介，不为凑风格统一加海报、开屏或插画。

## 参考要能进入画面

用户参考和认可版本优先。开放任务的资料不足时，少量查看目标相近与跨领域的具体页面，借鉴构图、图形、排版或反馈的机制。用一句话记录“借什么、用在哪里、依据是什么”。产品功能介绍支持业务判断，不能充当视觉参考。

需要还原效果、分析机制或用户指出效果不对时，检查可访问的 HTML/CSS/JS、实际资源、运行 DOM 与中间状态，再决定实现。分清源码确认、实际观察和待验证推测；读不到就说明限制。直接复用代码或素材核对许可；学习机制可以独立实现，保留来源但不照搬功能清单。

## 先做最能判断方向的部分

把说明落实为带真实内容、主要图形和字级的代表画面，再连起一段主要操作到结果。可以使用有标注的演示数据和局部真实机制；小样应足以判断观感与用法，尚未选择时不把所有路线都扩成完整产品。

多路线比较分别看产品路径和视觉表达：前者改变用户怎样完成目标，后者改变画面怎样组织和传达它。保留共用事实与数据规则；主画面、导航、密度、图形和反馈从各自构思生长，避免共用外壳先锁死所有路线。颜色、名字或外层布局的变化不足以代表整套视觉方向。

保存小样后再选择，选择转成可观察的成品条件，再扩展完整流程。明确获准模拟选择的评测也按此顺序记录；保存选择前的实际文件，而不是成品完成后补一张方案说明。

## 用画面和动作判断完成

在同一宽屏与窄屏看实际截图：视觉重心是否服务主任务，主操作是否及时可达，真实长短内容、图形与留白是否协调，各页面是否来自同一套构思。观察完整动作的中间态、结束态、快速重复和减少动态效果；运动应说明操作造成的变化。

发现偏差先修构图、素材或状态衔接的原因，再检查受影响路径。业务正确、无报错和动画有播放分别证明对应行为；审美差异、使用负担和成品一致性需要另外观看与操作。达到当前选择所需的判断程度就提问，达到成品条件就交付。

方法借鉴本地 `build-websites-v2` 的参考拆解、素材构图与实际体验核验，以上为独立整理；不依赖该 Skill 安装，也不把其特定视频模式作为通用要求。
