# Co-Decide 0.6.0 与原版正常 Codex：配对实测

日期：2026-10-11。结论：本轮证明了选择过程更具体、可回看，没有证明关键偏好识别或最终产品普遍优于原版，也没有证明选择机制节省 token。简历这一可靠配对中，成品同样达线，插件 token 增加约 77.3%。

## 怎么比较

真实启动 8 次 Codex CLI 独立运行，形成 4 对、3 个领域。借还的审批与直接登记是同一原目标和材料的两个相反偏好，不算两个独立领域。固定 gpt-6.1-sol、ultra、CLI 0.162.0-alpha.17.2；原版保留正常提问、小样、研究、修改和检查能力，没有人为要求先做错。

三种初始请求分别是“给家里做个物品借还工具。”“用这份经历做一页求职简历。”“修好这个金额分摊函数：数量必须是正整数，优惠后不能出现负数，分摊金额加总必须等于实付。”原始材料同配对逐字节一致，额外偏好在运行前冻结；仅回答实际问到的维度。初次可验收成品出现后，才反馈最高优先级未满足项。两组各最多四次反馈、两次成品后修订。

为避免既有插件和记忆污染，两组在独立测试目录关闭插件生态和记忆，仅处理组通过本地 Skill catalog 暴露冻结的同一 SKILL.md。这是在比较插件的单 Skill 行为，不是测试安装器，也不是完整默认桌面环境。核验实际 catalog：所有普通 Skill 相同，原版没有暴露或读取 co-decide，三项开放任务处理组均读到同一冻结 Skill。金额负对照未读取它，结果仍保留。

原先预注册希望关闭多 agent，但进程参数 features.multi_agent=false 实际未禁用委派。两组都使用了相同的实际委派能力。这项预注册条件未满足，必须披露；计量因此改为主线程和递归子线程完整树。不能将参数写了就当作生效。此前项目目录内的污染试运行已作废，日志保留，不进入有效样本。

## 成品与成本

表中先列首次实际可用成品，再列相同反馈后的最终成品。分母是每个任务全部固定条件，跨领域分母不同，不加总为能力排行。金额表按 4 项功能标准，每组另有相同的 61 项独立函数验收全部通过。

| 配对 | 原版：首次 → 最终 | 插件：首次 → 最终 | 原版完整树 token | 插件完整树 token | 解释 |
|---|---:|---:|---:|---:|---|
| 借还：物主审批 | 5/5 → 5/5 | 5/5 → 5/5 | ≥3,144,776 | 2,490,345 | 不计算节省比例：有中断计量未闭合 |
| 求职简历 | 4/4 → 4/4 | 4/4 → 4/4 | 393,842 | 698,357 | +77.3% |
| 金额函数修复 | 4/4 → 4/4 | 4/4 → 4/4 | 715,239 | 478,257 | -33.1%；负对照未读核心 Skill，不能归因 |
| 借还：直接登记 | 5/6 → 6/6 | 5/6 → 6/6 | ≥4,287,080 | 3,940,670 | 不计算节省比例：有中断计量未闭合 |

审批原版首次尝试在 480 秒阶段超时后缺少 store.js，按钮无法运行；这不是可用首次成品。相同预算内的一次“继续完成”技术恢复后，首次可用成品与最终均为 5/5。该失败及恢复成本计入，不能把技术超时归为选择机制不足。两种直接登记首次成品各 5/6，均缺撤销；此前用户只回答直接登记，撤销偏好尚未披露，因此不是忽略反馈。两组收到同一句“借错和归还错都能撤销，恢复到刚才操作前的状态。”后，各在一次成品后修订中完成验收。

简历均实际渲染为可读的 A4 一页，没有夸大指导完成、Stub 或 DemoChatModel 的经历。R02/R03 的责任和事实边界来自原材料，不算插件额外发现的用户选择。两借还审批品均跑通角色切换、申请、物主确认、归还、刷新、防重复以及首页待处理事项。直接登记修订版真实操作了借用撤销、归还撤销及刷新，恢复到原借用人和原状态。借还均为单浏览器内两名虚构成员的本地演示，不证明真实多用户权限或跨设备服务。

独立金额验收：每组 Tests run: 61，Passed: 61，Failures: 0，Errors: 0，Skipped: 0；validation SUCCESS；BUILD 不适用。采用相同 exact Fraction oracle，含非法输入、布尔值数量、零额、优惠过大、超大整数、尾差与顺序、无写文件行为。作者各自新增的测试数量不用于组间质量打分。

简历及借还由不知道组别和 token 的独立模型审查者匿名验收，使用真实 Edge、页面/PDF 图像和前台操作；并非真人满意度测试。原简历评测 JSON 中“人工”措辞已纠正，实际从未有人类评审。H237 审查过程中收到另一匿名候选缺文件的信息，限制了评审完全独立性；没有收到组别或 token。功能执行证据仍保留，不能将这个限制隐去。

直接登记初版的三个独立呈现维度（可用性、信息组织、表达，各 0–2）为原版 1/1/2、插件 1/2/2，插件首页较易比较；两个产品都存在功能缺项，不能用呈现分掩盖。后续修订原版自行修复了布局，两组最终均为 2/2/2；初版的呈现差异没有延续为最终优势。这是少量模型主观评分，不是用户偏爱或统计优势。

## 用户选择有没有真的参与

| 指标 | 原版 | Co-Decide | 能说明什么 |
|---|---|---|---|
| 三项开放场景定型前识别主要选择 | 3/3 | 3/3 | 本轮没有更早识别的优势 |
| 审批选择最终兑现 | A01 通过 | A01 通过 | 两边都按用户答案改变状态流 |
| 简历岗位选择最终兑现 | R01 通过 | R01 通过 | 两边都定位 Java 后端实习 |
| 直接登记及后来撤销选择 | D01/D02 最终通过 | D01/D02 最终通过 | 两边后续选择均实际落地 |
| 相反答案是否改变借出机制 | 审批/直接登记为不同状态流 | 审批/直接登记为不同状态流 | 反事实效果两边都有 |
| 借还文件小样可回看 | 未保留对照小样 | 两份真实 HTML 对照保留 | 本轮确认的过程差异 |
| 直接登记成品后偏好修订 | 1 次 | 1 次 | 本轮没有减少这类返工 |

问题调用数也是两组各三个开放场景一次、金额零次；数量不构成优势。候选更多、模型写得更长、用户回复更频繁，都不是共同决策质量的替代。模拟用户预先固定偏好，不能测量“看完小样才发现自己想要什么”的真人收益，也不能评价决策信心。

## token 账怎么算

从原生日志 token_usage_record 读取自身线程的原子 response_id 用量、去重并核对累计值；子线程出生/继承历史边界之前的父历史剔除，每个递归后代只算一次。包含小样、询问、读取、实现、失败、恢复及修订，不只计最终回复。input 已含 cached_input，output 已含 reasoning；原始总量为 input+output，缓存和推理不再相加。

| 运行 | 组别 | 输入 | 缓存输入（子集） | 非缓存输入 | 输出 | 推理输出（子集） | 完整性 |
|---|---|---:|---:|---:|---:|---:|---|
| P01 | 原版 | 3,098,428 | 2,920,576 | 177,852 | 46,348 | 7,578 | 观察下限 |
| P02 | 插件 Skill | 2,435,620 | 2,299,904 | 135,716 | 54,725 | 11,237 | 完整 |
| P03 | 插件 Skill | 685,927 | 635,904 | 50,023 | 12,430 | 5,414 | 完整 |
| P04 | 原版 | 385,088 | 351,488 | 33,600 | 8,754 | 3,563 | 完整 |
| P05 | 原版 | 707,005 | 639,488 | 67,517 | 8,234 | 2,146 | 完整 |
| P06 | 插件 Skill | 469,787 | 427,904 | 41,883 | 8,470 | 2,424 | 完整 |
| P07 | 插件 Skill | 3,878,892 | 3,682,560 | 196,332 | 61,778 | 15,248 | 完整 |
| P08 | 原版 | 4,230,400 | 4,034,048 | 196,352 | 56,680 | 12,046 | 观察下限 |

≥ 表示已经观测到的用量下限。原版两借还运行有被中断子线程在末次已计量记录后继续生成、缺少可确认的最终结账记录；不能把未知费用当零，按预注册规则不计算节省比例。处理组两借还的已记录完整量低于原版已记录下限，这个观察保留，但伴随技术超时、委派差异和单次生成，不能据此宣称选择机制的因果节省。

缓存输入占比较高，原始 token 不是新生成文字量，也不直接等于费用、人民币或订阅额度。简历配对中处理组非缓存输入约 +48.9%、输出约 +42.0%，说明额外成本不能只用缓存解释。金额虽然处理组原始 token 约 -33.1%，但核心 Skill 未读取、没有选择机制介入，不是插件协作收益证明。评测组织、模拟用户、独立盲评及作废试运行费用没有完全计量，未加入任一产品组，也没有声称是零或评测本身省 token。

阶段时间限制均为 480 秒；初始提问阶段由测试器注入模拟答案，中断的是本轮自己的 CLI 进程。审批原版与两个直接登记初次实施发生阶段超时，失败和等待中生成保留记账。初始暂停不是技术失败。不比较完整用户等待耗时，也没有测试桌面选项消失时间、90 分钟等待或原生 UI 卡片。

## 插件适合承担什么责任

已证实的特长是把选项变成能看懂后果的小样，并保留回看材料；它把原版已有的能力组织成固定协作过程。最值得特化的是用户偏好尚未形成、单靠文字难比较、晚改会重做主体的任务。本轮没有证明这类收益在真人身上发生，也没有证明常规明确任务需要这层流程。

开发评价已改为“定型前选择影响、选择兑现、答案改变后的产品差异、同等验收成本”，见选择效果协议。下一阶段应压缩小样投资：机制取舍先用最短的真实状态对照，只有文字难判断的操作或视觉差异才做文件样板；把节省出来的预算投入每条已选条件的实际验收。此改进尚未改入运行 Skill 或实测，不宣传收益。

本轮只新增评测协议、试验与报告；冻结 Skill、安装缓存、用户和限定项目配置的 SHA 均未改变，两份配置仍可作为 TOML 解析。没有重新安装、改配置或推送 GitHub。八次单次生成、三个领域、模拟偏好和共同环境限制不足以证明普遍优于正常 Codex，尤其不能把原版也会主动提问删掉，制造“传统多轮修改”必输的对手。
