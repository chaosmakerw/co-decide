# 精简候选与成本复测

本轮改动已经写入仓库源码，保持现有发布元数据 0.6.0，不同步安装缓存、不写 Codex 配置、不发布。结果是：候选在一个交接任务中守住同一验收线，成本比旧版降低；仍未证明成品更好或比原版成本更低。

## 实际改动

- **先决定用途。** 讨论成果要解决什么问题；实现载体由 agent 处理，只有载体影响用途或可用范围时才问。减少先选文件格式、随后仍要猜用途的无效参与。
- **同一输入看后果。** 候选比较用户会看到什么、做什么及主要代价。有材料依据的受阻情形才加入对照，不把假想风险变成需求。
- **按判断需要制作小样。** 正文片段或路径足以判断就复用正文，操作或视觉差异才做可运行小样。整体布局、核心流程仍须覆盖完整结构或路径；没有以省成本为由缩成孤立组件。
- **对照用于验收。** 反馈直接形成一句话或至多三项可观察条件，不加确认仪式；用原场景检查承诺，再检查一个有依据的不同输入，完整成果仍按原目标验收。
- **加强等待。** 提问立即进入等待，工具的 `accepted` 回执不是用户答案。保留一次一题、全任务及子 agent 暂停、超时后再等90分钟、正文保留完整选项和小样入口。
- **精简入口。** 核心从 3,803 字符 / 10,607 UTF-8 字节降至 2,074 字符 / 5,786 字节，字节体积减少45.45%。仍只有一个 SKILL.md，没有新增常驻服务或运行配置。体积减少不等于运行 token 同比例减少。

## 测试如何进行

自然输入只有“把这些交接材料整理成新人接手后能直接用的东西。”材料是一场合成活动的接待交接，包含名单、变更场地及现场问题。开始前冻结偏好：新人按眼前问题找到处理办法、先看到动作与回应。只回答模型实际问到的维度；问形式时只委托形式，不提前泄露主体组织偏好。

原版保留提问、研究、小样及委派能力。各组使用实际继承的 gpt-6.1-sol / ultra、相同材料与提示，插件生态和记忆仅通过测试进程参数关闭，没有写配置。旧版及候选从各自隔离目录的 Skill catalog 加载，真实读取核心文件；原版目录没有核心 Skill。每个完成样本实际包含一个子 agent，费用递归计入自身线程，剔除复制的父历史与重复 response_id。

验收 H00 可读入口与本地引用、H01 原材料事实、H02 四场景的动作/话术/必要升级、H03 不捏造信息、C01 主体按问题检索。独立模型只看到匿名产品、材料及标准，用真实 Edge 核对链接、下载和打印，并读取 PDF；没有固定页数或必交 PDF 的额外要求。匿名审查是模型评估，不是真人满意度。

## 真实结果

| 样本 | 成品验收 | 等待协议 | 总 token | 非缓存输入 | 输出 |
| --- | --- | --- | ---: | ---: | ---: |
| 原版 T01 | 5/5 | 未提问，不适用 | 359,757 | 42,620 | 11,089 |
| 旧版0.6.0 T02 | 5/5 | 问形式，收到实际委托后继续 | 1,372,889 | 68,867 | 23,382 |
| 第一候选 T03 | 5/5 | **失败：未回答便按推荐实现** | 923,115 | 49,999 | 16,156 |
| 最终候选 T04 | 5/5 | 未提问，不适用 | 715,208 | 53,542 | 17,186 |

四个样本均完成，无交付后修订；原版和最终候选直接把材料组织成可用成品。旧版只问了纸面交接包或离线签到页面，模拟用户回答“形式你决定，能直接用就行。”这是局部委托，不是确定了主体用途。

最终候选比旧版总 token 少 **47.90%**，非缓存输入少22.25%，输出少26.50%；比原版总 token 多 **98.80%**，非缓存输入多25.63%，输出多54.98%。总量含缓存输入，缓存及推理是子集，不能再次相加；这些是 token 数，不是费用、人民币或订阅额度。

四个应用执行样本合计3,370,969 token，包含被拒候选。定向等待样本、反馈器、匿名评审和本插件研发费用另属评测成本，未完整计量，不能从表中推导整个开发过程省了多少成本。

5/5是成品标准，不是五个用户选择。在这个任务中，原版已经独立满足未披露的偏好，最终候选没有展示不同选择后的成品分支。本轮不能据此计算选择兑现率、声称用户参与更多或证明选择机制优于原版。它支持减少旧版无效形式提问及冗余开销的方向，不支持普遍优越性结论。

## 失败与修复证据

第一候选 T03 发出问题并收到 `{"accepted":true}`，在没有实际答案的情况下进入主产物制作。虽然产品验收通过，该候选仍因等待协议失败被拒绝，不把它记为成功节省成本。

修复后保留明确的“提交回执不算答案”和提问后立即等待规则。用另一个自然目标“帮我们四人宿舍做一个能实际使用的习惯打卡程序”定向复测：实际出现手机共享与一台电脑轮流使用的后果对照，收到 `accepted` 后未答。观察约151.6秒，只有等待和计时，没有生成主程序；读取时钟并设定一次再等90分钟的截止时间。随后测试器显式中断等待并关闭自己的服务，未假造用户选择。没有验证完整90分钟、原生卡片寿命、回答后的恢复或实际四人共享成品。

最终源码 SHA-256：`03440544b75c0d28fb964a11a32a078d39ff0c1620c4a90422c6e2d3b85567ae`。最终完整产品另起 T04 新运行；它是在观察回归后进行的探索性复测，不是原预注册三组中的未修改候选。
