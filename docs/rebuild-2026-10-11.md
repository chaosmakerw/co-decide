# 面向产品与业务的重建（2026-10-11）

本轮重新构建运行 Skill，重点收窄到产品与界面设计、软件业务设计。用户只给自然目标，agent 找出重要取舍，用同一输入展示整体路线，将实际回答变为可观察的成品条件。发布元数据仍为0.6.0；本轮没有安装、推送或修改 Codex 配置。

## 改动

- 选择影响整个产品：界面的内容主次、结构、构图、视觉与主操作共同变化；业务的参与者、生效状态、责任与异常共同变化。整体视觉偏好本身可以构成重要选择。
- 先做足以判断的对照，再完善选定路线。优先两条主路线；更多候选应提供新的重要后果，协作共用资料与实现，不为每条候选复制完整任务。
- 小样验证以选择依据为界，完整可靠性与边界检查留到选定后。保留一次一题、明确反馈才恢复、选择验收与小样回看。

重建第一候选为4003字节，SHA256 `1d02395e18adf9ba05e68d44669d1944757ae100746398b13f16ab2bde67e14c`。实际阅读预览展开了三份较完整的独立实现，发现预算仍过多用于回答前。第二候选补入后两条成本规则，为4287字节、1547字符，SHA256 `7972948aed9389e53bf0d0f0275f4b52f82e74ae242e711f295a404cca293576`。

## 比较方法

每案各一个原版成品、两个插件选择结果，均独立开始。原版保留提问、设计、工具和协作能力；不强迫它直接执行或故意做差。每条完整路线单独计入自身递归执行树的 token，缓存输入与推理输出为子集，不重复相加。不把两份插件成品的总成本对比一份原版，也不摊薄共享成本。

初始目标仅为“帮我做一个管理个人阅读的工具”和“给我们小团队做一个请假管理工具”。提供相同合成 CSV 和本地演示边界，没有在提示中指定讨论点、预览、风格、布局或生效规则。模拟偏好与共同验收在运行前冻结，只回答模型实际问到的维度；未问偏好只能在首份可用成品后作为最多一次修订。

阅读偏好分别是舒展的书刊浏览、紧凑的行动工作台；业务偏好分别是直接登记生效、负责人确认后生效。共同检查真实主操作、状态反馈、刷新保存与合成资料准确；偏好兑现、整体差异、使用负担分别记录。匿名评测人员不读取 Skill、实验组映射和成本，使用真实 Edge 控件检查应用，作者自报测试不代替独立验证。

环境继承相同 gpt-6.1-sol/ultra，未调整模型或推理档位。第一轮部分运行触及测试器900秒上限，保留中断记录并通过同 threadId、同原生日志、同 cwd 的原线程续跑；输入仅为“继续完成已选定的目标并收尾”。中断或缺失计量不按零处理，不据未完成结果宣称成本优势。

## 验证边界

真实 `turn/steer` 回执、随后原生用户消息和模型采纳分别核验，送出成功不等于收到答案。回答由冻结的模拟用户提供，不能宣称真人满意度或完整90分钟等待已验证。

第二候选隔离打包实测：Tests run 51，Passed 51，Failures 0，Errors 0，Skipped 0，BUILD SUCCESS。此为七文件结构和 ZIP 内容检查，不是51次协作行为测试。既有发布文件与安装缓存不随候选包更新。

整体路线确实改变了最终结构与行为。原版阅读也有完整封面和舒展书架，不能仅凭插件有两种结果便宣称单件品质优胜。辅助字体偏小、部分首页书籍位置较低、额外日历或额度假设分别记录为负担。请假三份仍偏绿色浅色后台，业务差异兑现不能当作视觉风格突破。确认路线初版存在跨身份导航问题，作者自行修复后再验收通过；深色阅读的小样暗字与控件轮廓问题在最终版自行修复，未由评测者免费改产品。

## 成本结果

每行是一条独立成品路线，含其完整递归子任务、制作小样、失败尝试和原线程续跑。总量包含缓存输入；未缓存输入和输出单列，不能直接等同付费金额。外部插件开发、协调与匿名验收成本未并入单条成品指标，也没有当作零或声称整个实验省钱。

| 成品路线 | 总 token | 未缓存输入 | 输出 | 计量完整 |
| --- | ---: | ---: | ---: | --- |
| 阅读原版 | 4,650,141 | 212,843 | 80,946 | 是 |
| 阅读 v1 A | ≥5,343,417 | ≥245,993 | ≥110,032 | 否，缺中断尾段 |
| 阅读 v1 B | 6,967,591 | 264,801 | 81,222 | 是 |
| 阅读 v2 A（展示） | ≥3,926,665 | ≥215,543 | ≥71,826 | 否，缺中断尾段 |
| 阅读 v2 B（展示） | 6,230,017 | 295,852 | 122,965 | 是 |
| 请假原版，含修订 | ≥8,989,263 | ≥413,693 | ≥123,346 | 否，缺中断尾段 |

同一登记偏好 A 的请假路线，插件完整计量比原版已记录下限少至少 **36.8%** 总 token；未缓存输入少至少48.6%，输出少至少39.1%。两份最终产物都兑现登记生效，插件在重写前澄清规则。该结果支持“重要业务分歧提前选择可以减少返工”，但只观察了一次，不能保证所有任务更好、更省。

阅读首轮候选过重。v2 把三条较完整预览收紧为两条整体路线，真实重跑后均兑现选择。B 路线总 token 比自身 v1 少10.6%，但未缓存输入和输出分别增加11.7%、51.4%，不能只挑总量宣布成本改善。A 路线有中断尾段缺计量，不能用较低观察值宣称节省；B 与原版对应不同偏好，也不能当作严格同产品胜出。**界面方向尚未证明稳定达到相近成本，本轮不宣布普遍超越原版。**

业务两份测试使用 v1 核心；最终 v2 新增成本规则的真实新模型测试仅覆盖阅读 A/B。不同 SHA 的结果不混记为最终源码全量验证。后续若继续验证，应冻结偏好、分别重复同类比较，保留失败和全部消耗，不追加细枝末节问卷。
